# RENT.EVENT — локальный MVP

Демонстрационный прототип сервисного маркетплейса локальной аренды оборудования для мероприятий. Проект показывает ключевую гипотезу: организатор может найти подходящее оборудование, выбрать даты и отправить структурированную заявку, а владелец — добавить свою позицию в каталог.

## Что реализовано

- Каталог тестовых предложений: свет, звук, эффекты и видео.
- Поиск по названию и описанию, фильтр по категории, сортировка по цене.
- Форма бронирования с датами, контактами и проверкой диапазона дат.
- Расчёт стоимости аренды по количеству дней.
- Сохранение заявок и новых предложений в `localStorage`.
- Просмотр списка созданных бронирований.
- Форма добавления оборудования от владельца.
- Адаптивная вёрстка для компьютера и телефона.

## Технологии

- HTML5 — структура экранов и форм.
- CSS3 — адаптивный интерфейс и визуальная система.
- JavaScript (ES6+) — каталог, фильтрация, валидация, расчёт стоимости и обработка заявок.
- Web Storage API (`localStorage`) — локальное хранение данных в браузере.

## Как запустить на macOS

**Вариант 1 — без установки дополнительных программ**

1. Скачайте архив и распакуйте его.
2. Откройте папку `equipment-marketplace-mvp`.
3. Дважды нажмите `index.html` или откройте его через браузер.
4. Каталог и сценарии будут работать локально.

**Вариант 2 — через Visual Studio Code / Visual Studio**

1. Откройте папку проекта в редакторе.
2. Откройте `index.html` в браузере. При наличии расширения Live Server можно запустить страницу через него, но это необязательно.
3. Для Visual Studio на Mac можно открыть папку как проект/набор файлов; сборка не требуется.

## Пользовательский сценарий для демонстрации

1. В каталоге найдите «Генератор тяжёлого дыма».
2. Нажмите «Забронировать».
3. Укажите даты, имя и контакт, отправьте заявку.
4. Нажмите «Мои бронирования» — заявка и сумма отобразятся в списке.
5. В блоке «Для владельцев» добавьте оборудование — новая позиция появится в каталоге.
6. Обновите страницу: данные останутся в этом браузере благодаря `localStorage`.

## Архитектура и ограничения MVP

В текущем прототипе нет отдельного серверного backend: бизнес-логика выполняется в браузере, а `localStorage` играет роль простого локального хранилища. Это позволяет показать работающую механику без сервера и регистрации. Данные доступны только в том браузере и на том устройстве, где создана заявка.

Не реализованы реальные платежи, escrow/холдирование, проверка личности, юридически значимый договор, синхронизация между пользователями и серверная проверка доступности. Статусы заявок демонстрационные. Для промышленной версии потребуются backend API, база данных, авторизация, интеграция платёжного провайдера и юридическая проработка безопасной сделки.
